# Langfuse Tracing Integration Plan

## Overview
Integrate Langfuse observability into BearBot to provide full tracing of the forecasting pipeline: from batch processing → individual questions → research API calls → forecasters → LLM calls.

## Implementation Status
✅ **COMPLETED** - All files have been updated with Langfuse tracing

## Key Implementation Details
- **SDK Version**: Langfuse SDK v3+ with `@observe` decorator
- **Context Propagation**: Automatic via decorators
- **Update Methods**: Type-specific methods:
  - `get_client().update_current_span()` for spans
  - `get_client().update_current_trace()` for traces
  - `get_client().update_current_generation()` for generations

## Target Trace Hierarchy
```
Trace: Forecast Batch
├─ Span: Forecast Question (post_id=123)
│  ├─ Span: Research (provider=perplexity)
│  └─ Span: Binary Forecaster
│     ├─ Generation: LLM Call (run=1)
│     ├─ Generation: LLM Call (run=2)
│     └─ Generation: LLM Call (run=3)
└─ Span: Forecast Question (post_id=456)
   ├─ Span: Research (provider=exa)
   └─ Span: Numeric Forecaster
      ├─ Generation: LLM Call (run=1)
      ├─ Generation: LLM Call (run=2)
      └─ Generation: LLM Call (run=3)
```

## Trace Metadata Strategy

**Batch Level (Trace)**:
- num_questions, submit_prediction, num_runs_per_question, skip_previously_forecasted

**Question Level (Span)**:
- question_id, post_id, question_type, title (truncated)

**Research Level (Span)**:
- provider, question (truncated), result_length

**Forecaster Level (Span)**:
- question_type (auto-captured by @observe)

**LLM Call Level (Generation)**:
- question_type, run number
- model, temperature, tokens (auto-captured by Langfuse OpenAI integration)

## Edge Cases

1. **Langfuse Disabled**: All code gracefully degrades via `settings.langfuse_enabled` checks
2. **Missing LLM Responses**: Existing error handling preserved; Langfuse captures exceptions
3. **Rate Limiting**: asyncio.Semaphore works unchanged; Langfuse wraps the actual API call
4. **asyncio.gather Context**: @observe decorator uses OpenTelemetry for automatic propagation
5. **Error Handling**: return_exceptions=True preserved; failed spans show errors in UI
